# hurdle-ledger 共同账户账本

一个纯静态网站，部署在 GitHub Pages 上，用来记录两人共有的投资账户的收益和分成（份额法 + 6% 门槛 + 高水位线 + 25% 分成）。

**仓库是公开的，但里面没有任何明文数据。** 所有记录和截图都在浏览器里用密码加密（PBKDF2-SHA256 600000 次 + AES-GCM-256）之后才上传。密码不存放在任何地方，解密后的数据只保存在浏览器内存中，忘记密码就无法恢复数据。

| 文件 | 作用 |
|---|---|
| `index.html` | 查看页：输入密码 → 解密 → 展示 |
| `editor.html` | 编辑页：录入数据、上传截图 → 导出加密文件 |
| `calc.js` | 全部计算逻辑（公式写在文件开头的注释里） |
| `crypto.js` | 加密 / 解密 |
| `github.js` | 编辑页直接提交到仓库（自动发布） |
| `view.js`、`style.css`、`zip.js` | 页面渲染、样式、手动导出打包 |
| `data.enc` | 加密后的全部记录（第一次由编辑页生成后上传） |
| `shots/` | 加密后的截图，一张一个文件 |
| `tests/` | Node 单元测试（只用虚构的测试数据） |

## 开启 GitHub Pages

1. 打开仓库 → **Settings** → 左侧 **Pages**。
2. **Build and deployment** → Source 选 **Deploy from a branch**。
3. Branch 选 **main**，目录选 **/ (root)**，点 **Save**。
4. 等 1～2 分钟，页面顶部会显示网址，一般是 `https://<用户名>.github.io/hurdle-ledger/`。
   - 查看页：`…/hurdle-ledger/`（把这个网址发给朋友）
   - 编辑页：`…/hurdle-ledger/editor.html`（自己用）

## 朋友怎么看

朋友不需要下载任何东西：用手机或电脑浏览器打开查看页网址，输入密码即可。页面开着时每 3 分钟会自动检查一次新数据（切回这个页面时也会检查），有更新就自动刷新。也可以点右上角的“刷新”。

## 创建 GitHub token（自动发布用，只需做一次）

1. 登录 GitHub → 右上角头像 → **Settings** → 左侧最下面 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. Token name 随便填，例如 `hurdle-ledger`；Expiration 选一个期限（例如 1 年，到期后重新生成）。
3. **Repository access** 选 **Only select repositories**，只勾选 `hurdle-ledger`。
4. **Permissions → Repository permissions** 中，把 **Contents** 设为 **Read and write**，其他保持默认。
5. 点 **Generate token**，复制以 `github_pat_` 开头的字符串，保存在你的密码管理器里。**不要把它发给朋友，也不要提交到仓库。**

这个 token 只能读写这一个仓库的文件。编辑页只把它保存在页面内存中，关闭或锁定页面后就清除，下次编辑时重新粘贴。万一泄露，在同一页面点 **Revoke** 作废，再生成一个新的。

## 第一次使用

1. 打开编辑页，在“新建数据集”中填写双方名称、首笔资金日期、我的首笔投入 A、朋友的首笔投入 B，并设置密码（建议 12 位以上，不要用生日等容易猜到的内容）。
2. 在“自动发布到 GitHub”中粘贴 token，点 **连接**。页面会自动把加密后的 `data.enc` 提交到仓库。
3. 把查看页的网址和密码分别发给朋友（最好用不同的渠道发送）。

## 每季度更新（季末后做一次）

1. 打开编辑页 → 输入密码 → **从本站加载 data.enc** → 在“自动发布到 GitHub”中粘贴 token，点 **连接**。
2. 在“季度快照”中填写：
   - **日期**：记录账户总值的那一天，一般是季度最后一天。**年末一定要有 12 月 31 日的快照**，否则那一年无法结算分成。
   - **期间**：会根据日期自动填写（如 `2026Q3`），一般不用改。
   - **账户总值**：当天收盘后的账户总资产，已经包含当天所有的注资和提取。
   - **截图**：选择券商 App 的资产截图。上传后会自动压缩并加密。
3. 点 **新增**。下方的“计算结果预览”会立即更新，核对净值、两人价值、门槛线和预估分成是否合理。12 月 31 日的快照会自动做年末结算（把分成对应的份额从朋友名下转到我名下）。
4. 保存后约 2 秒会自动加密并提交到仓库（顶部状态显示“已发布”），截图一起提交。约 1～2 分钟后查看页自动更新。

## 记录注资 / 提取（每次发生时都要记）

1. **在钱转入或转出账户之前**，先记下账户当时的总值（即“当时账户总值”）。如果当天已经收盘，就用收盘后的总值。
2. 打开编辑页，加载数据并连接 GitHub，在“资金流动”中填写日期、谁、注资还是提取、金额、当时账户总值。
3. 表单下方会即时显示当时的净值和对应的份数，提取时还会显示本人当时的持有价值。
4. 页面会自动校验：提取不能超过本人当时的价值；朋友提取时，还必须留够当时的预估分成。校验不通过的记录无法保存。
5. 同一天有多笔资金流动时，按实际先后顺序逐笔录入，每笔都填写**它自己**发生前一刻的账户总值。
6. 保存后自动发布。

## 发布冲突

如果在你加载数据之后，仓库里的 `data.enc` 被别处更新过（例如在另一台设备上发布过，或刚发布完 1～2 分钟内就重新打开编辑页、加载到了旧版本），发布会被拒绝，不会覆盖。此时点 **从仓库重新加载最新数据**，再重新录入刚才的修改。

## 不用 token 时：手动导出和上传

不连接 GitHub 也能用：点 **手动导出**，下载 `data.enc`（有新截图时是一个 zip），然后按下面的方法上传。

### 上传方法（GitHub 网页版）

1. 打开仓库首页 → **Add file** → **Upload files**。
2. 把 `data.enc` 拖进去。如果有截图，把 zip 解压，把整个 `shots` 文件夹一起拖进去（GitHub 会保留文件夹结构，同名文件会被覆盖）。
3. 点 **Commit changes**。1～2 分钟后刷新查看页即可看到更新。

手机上也可以操作：用浏览器打开 github.com 的仓库页（选“桌面版网站”），同样使用 Upload files 上传。

## 修改密码

1. 编辑页 → **修改密码**，输入当前密码和新密码。
2. 页面会从本站下载每一张截图，用旧密码解密，再用新密码加密。如果有截图本站没有，可以从本地选择对应的 `.enc` 文件补上。
3. 点 **确认使用新密码**。已连接 GitHub 时会自动把 `data.enc` 和全部截图重新发布；否则点 **手动导出**，把 zip 里的 `data.enc` 和整个 `shots` 文件夹全部上传，覆盖原文件。
4. 把新密码告诉朋友。

## 运行测试

需要 Node.js 22 或更新版本，不用安装任何依赖：

```bash
node --test tests/*.test.mjs
```

## 注意

- 不要把明文数据、明文截图或密码提交到仓库，包括 issue 和提交说明。
- `robots.txt` 禁止所有爬虫，所有页面都带 `noindex`。但网址本身是公开的，安全性完全依赖密码强度。
- 编辑页有未导出的修改时，关闭页面会弹出提醒。
