# hurdle-ledger 共同账户账本

中文 | [English](README.en.md)

一个纯静态网站，部署在 GitHub Pages 上，用来记录一位管理人和多位朋友（出资人）共有的投资账户的收益和分成（份额法 + 门槛 + 高水位线 + 分成；默认门槛 6%、分成 25%，可以按人单独设置）。随时可以有新朋友加入。

**仓库是公开的，但里面没有任何明文数据。** 所有记录和截图都在浏览器里用密码加密（PBKDF2-SHA256 600000 次 + AES-GCM-256）之后才上传。密码不存放在仓库里，解密后的数据只保存在浏览器内存中，忘记密码就无法恢复数据。

| 文件 | 作用 |
|---|---|
| `index.html` | 查看页：输入密码 → 解密 → 展示 |
| `editor.html` | 编辑页：录入数据、上传截图 → 自动发布到仓库（或手动导出） |
| `calc.js` | 全部计算逻辑（公式写在文件开头的注释里） |
| `crypto.js` | 加密 / 解密 |
| `github.js` | 编辑页直接提交到仓库（自动发布） |
| `view.js`、`style.css`、`zip.js` | 页面渲染、样式、手动导出打包 |
| `ocr.js`、`vendor/` | 截图自动识别总资产（Tesseract.js 本地副本，只在编辑页选截图时加载） |
| `data.enc` | 加密后的全部文字记录（第一次由编辑页生成） |
| `shots/` | 加密后的截图，一张一个文件 |
| `tests/` | Node 单元测试（只用虚构的测试数据） |

## 开启 GitHub Pages

1. 打开仓库 → **Settings** → 左侧 **Pages**。
2. **Build and deployment** → Source 选 **Deploy from a branch**。
3. Branch 选 **main**，目录选 **/ (root)**，点 **Save**。
4. 等 1～2 分钟，页面顶部会显示网址，一般是 `https://<用户名>.github.io/hurdle-ledger/`。
   - 查看页：`…/hurdle-ledger/`（把这个网址发给朋友）
   - 编辑页：`…/hurdle-ledger/editor.html`（自己用）

## 朋友怎么看

朋友不需要下载任何东西：用手机或电脑浏览器打开查看页网址，输入密码即可。页面开着时每 3 分钟会自动检查一次新数据（切回这个页面时也会检查），有更新就自动刷新；也可以点右上角的 **刷新**。

## 创建 GitHub token（自动发布用，只需做一次）

1. 登录 GitHub → 右上角头像 → **Settings** → 左侧最下面 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. Token name 随便填，例如 `hurdle-ledger`；Expiration 选一个期限（例如 1 年，到期后重新生成）。
3. **Repository access** 选 **Only select repositories**，只勾选 `hurdle-ledger`。
4. 在 **Permissions** 中点 **Add permissions**（或展开 **Repository permissions**），在搜索框输入 **contents**（输入“repo”是搜不到的），勾选 **Contents**，再把它右边的权限从 **Read-only** 改成 **Read and write**。Metadata（只读）会被自动加上，其他保持默认。
   如果列表里找不到 Contents，先回到第 3 步，确认选的是 **Only select repositories** 并且已经选中了 `hurdle-ledger`。
5. 点 **Generate token**，复制以 `github_pat_` 开头的字符串，自己保存好（例如存在密码管理器或备忘录里）。**不要把它发给朋友，也不要提交到仓库。**

这个 token 只能读写这一个仓库的文件。编辑页只把它保存在页面内存中，不交给浏览器的密码管理器，也不写入浏览器存储；关闭或锁定页面后就清除，下次编辑时重新粘贴。万一泄露，在同一页面点 **Revoke** 作废，再生成一个新的。

## 第一次使用

1. 打开编辑页，在“新建数据集”中填写管理人名称、第一位出资人名称、首笔资金日期、我的首笔投入 A、这位出资人的首笔投入 B（都必须大于 0），并设置密码（建议 12 位以上，不要用生日等容易猜到的内容）。
2. 在“自动发布到 GitHub”中粘贴 token，点 **连接**。页面会自动把加密后的 `data.enc` 提交到仓库。
3. 如果开户当天还有其他朋友一起投入，在“出资人”中添加他们，并填写“开户时投入”。
4. 把查看页的网址和密码分别发给朋友（最好用不同的渠道发送）。所有出资人共用同一个网址和密码，能互相看到彼此的数据，所以名称建议用昵称。

## 新朋友加入（中途加入）

1. 打开编辑页，加载数据并连接 GitHub。
2. 在“出资人”中点 **添加**：填写名称（昵称即可），“开户时投入”填 **0**。门槛收益率和分成比例留空就使用默认的 6% 和 25%，也可以为他单独填写。
3. 在“资金流动”中记录他的第一笔钱：“谁”选他，类型选 **注资**，并填写钱转入前一刻的账户总值。他按当时的净值买入份数，其他人的份数和价值不受影响。
4. 他加入那一年的门槛按这笔钱的**在账天数**折算（例如 10 月 1 日投入，到年末只算约 1/4 年的门槛）；从第二年起和其他人一样按全年计算。
5. 保存后自动发布，把查看页网址和密码发给他。

每位出资人的门槛、高水位和分成都**各自独立**计算。修改某人的比例会重新计算所有年份。有资金流动记录的出资人不能删除，需要先删除他的资金流动。

旧版本（只有一位朋友）的 `data.enc` 加载后会自动转换为新格式，原来的朋友成为第一位出资人，已有记录不变，计算结果也不变；下次发布时以新格式保存。

## 打开编辑页的三种方式

| 按钮 | 什么时候用 |
|---|---|
| **从本站加载 data.enc** | 日常更新：仓库里已经有数据，在它的基础上继续编辑。绝大多数时候用这个 |
| **选择本地文件…** | 手上有一个还没上传的 `data.enc`（例如以前手动导出没传的，或自己的备份）。加载后连接 GitHub 再发布即可 |
| **新建数据集** | 第一次使用，仓库里还没有任何数据 |

## 每季度更新（季末后做一次）

1. 打开编辑页 → 输入密码 → **从本站加载 data.enc** → 在“自动发布到 GitHub”中粘贴 token，点 **连接**。
2. 在“季度快照”中填写：
   - **日期**：记录账户总值的那一天，一般是季度最后一天。**年末一定要有 12 月 31 日的快照**，否则那一年无法结算分成。
   - **期间**：会根据日期自动填写（如 `2026Q3`），一般不用改。
   - **账户总值**：当天收盘后的账户总资产，已经包含当天所有的注资和提取。
   - **截图**：选择券商 App 的资产截图。会自动压缩并加密。
     选好截图后会**自动识别总资产并填入“账户总值”**（几秒钟；第一次要下载约 12 MB 的识别组件）。识别完全在浏览器本地进行，截图不会发到任何服务器。识别后会用“股票 + 理财 + 现金 = 总资产”核对，并在下方显示结果：
     - 显示 ✓ 表示和分项对得上；显示 ⚠ 时请对照截图核对金额。
     - 截图在券商的清算时间里时会提醒“资产统计可能有误差”，最好收盘清算后再截图。
     - 金额被 App 隐藏（\*\*\*\*）或找不到总资产时不会填入，请手动填写。
     - 识别过程中手动改过账户总值的话，不会覆盖你填的值，可以点“改用识别值”。
     - 先填账户总值再选截图也可以：识别结果会替换原值，并显示原值是多少。
3. 点 **新增**。下方的“计算结果预览”会立即更新，核对净值、每个人的价值、门槛线和预估分成是否合理。12 月 31 日的快照会自动做年末结算（每位出资人分别结算，把分成对应的份额从出资人名下转到我名下）。
4. 保存后约 2 秒会自动加密并提交到仓库（顶部状态显示“已发布”），截图一起提交。约 1～2 分钟后查看页自动更新。

同一个季度可以记录多次（日期不同即可，同一天只能有一条）。每条都会单独显示和计算；“相对上期收益率”是和紧挨着的上一条记录比较。

## 记录注资 / 提取（每次发生时都要记）

1. **在钱转入或转出账户之前**，先记下账户当时的总值（即“当时账户总值”）。如果当天已经收盘，就用收盘后的总值。
2. 打开编辑页，加载数据并连接 GitHub，在“资金流动”中填写日期、谁、注资还是提取、金额、当时账户总值。
3. 表单下方会即时显示当时的净值和对应的份数，提取时还会显示本人当时的持有价值。
4. 页面会自动校验：提取不能超过本人当时的价值；出资人提取时，还必须留够自己当时的预估分成。校验不通过的记录无法保存。
5. 同一天有多笔资金流动时，按实际先后顺序逐笔录入，每笔都填写**它自己**发生前一刻的账户总值。
6. 保存后自动发布。

## 修改、补录和查看记录

- 列表里每条记录都有 **编辑** 和 **删除**。补录以前的记录、修改日期都可以，保存后会自动按日期放到正确位置，之后的所有结果自动重算。
- 表格默认按日期排序，新的在上面。点任意列的表头可以按这一列排序，再点一次反向（▼ / ▲ 表示当前排序）。查看页的“季度明细”“资金流动明细”也可以这样排序。
- 编辑快照时重新选一张截图，会替换原来的截图。

## 发布

- 连接 GitHub 并勾选“修改后自动发布”后，每次保存都会自动发布，一般不需要手动操作。
- 顶部的 **立即发布** 按钮始终可以点：有修改时马上发布；没有修改时只会提示“仓库里已是最新数据”；还没连接时会打开连接设置。发布失败后点它就是重试。
- 每次发布都会在仓库里留下一个名为 “Update encrypted ledger data” 的提交，`data.enc` 和新截图在同一个提交里。

### 发布冲突

如果在你加载数据之后，仓库里的 `data.enc` 被别处更新过（例如在另一台设备上发布过，或刚发布完 1～2 分钟内就重新打开编辑页、加载到了旧版本），发布会被拒绝，不会覆盖。此时在“自动发布到 GitHub”里点 **从仓库重新加载最新数据**，再重新录入刚才的修改。

## 不用 token 时：手动导出和上传

不连接 GitHub 也能用：点 **手动导出**。没有新截图时下载 `data.enc`；有新截图时下载一个 zip（里面是 `data.enc` 和 `shots/xxxx.enc`）。截图只在导出前保存在页面内存里，导出一次后就不会再出现在下一次导出中，请确认 zip 已保存好。

### 上传方法（GitHub 网页版）

1. 打开仓库首页 → **Add file** → **Upload files**。
2. 把 `data.enc` 拖进去。如果有截图，把 zip 解压，把整个 `shots` 文件夹一起拖进去（GitHub 会保留文件夹结构，同名文件会被覆盖）。
3. 点 **Commit changes**。1～2 分钟后刷新查看页即可看到更新。

手机上也可以操作：用浏览器打开 github.com 的仓库页（选“桌面版网站”），同样使用 Upload files 上传。

## 修改密码

1. 编辑页 → **修改密码**，输入当前密码和新密码。
2. 页面会下载每一张截图，用旧密码解密，再用新密码加密。如果有截图下载不到，可以从本地选择对应的 `.enc` 文件补上。
3. 点 **确认使用新密码**。已连接 GitHub 时会自动把 `data.enc` 和全部截图重新发布；否则点 **手动导出**，把 zip 里的 `data.enc` 和整个 `shots` 文件夹全部上传，覆盖原文件。
4. 把新密码告诉朋友。朋友开着的查看页会提示输入新密码。

## 密码输入框

- 账本密码框是标准的密码框，浏览器可以记住密码并自动填充（保存时用户名显示为 `hurdle-ledger`）。
- 输入框右边的 **显示** 按钮会把它切换成普通文本框，这时输入法（包括输入法里的短语）可以正常使用；提交时会自动切回圆点。
- GitHub token 框不会被浏览器的密码管理器保存，避免覆盖账本密码。

## 页面上几个数字的含义

- 每位出资人有自己的一张卡片和一套数字；管理人卡片里的分成收入是所有出资人的合计。
- **年末门槛线（不提成线）**：按目前已发生的资金流动算出的年末门槛。年末出资人的价值不超过它，就没有分成。
- **当前门槛线**：按今天已过天数折算的门槛，用来估算“预估分成”。开户那一年，开户时首笔投入的门槛始终按全年满额计算，不折算；之后的注资、提取（包括中途加入的朋友的第一笔钱）按在账天数计算；从第二年起，期初高水位部分在年中按已过天数折算。
- **预估分成**：如果今天结算会产生的分成，只供参考，只有 12 月 31 日的快照才真正结算并转移份额。
- 完整规则写在查看页底部的“计算规则（通俗说明）”里，公式写在 `calc.js` 开头的注释里。

## 数据和备份

- `data.enc` 是唯一保存数据的地方（起始金额、出资人列表、全部快照和资金流动），必须叫这个名字、放在仓库根目录，不能删除。截图不在 `data.enc` 里，而是 `shots/` 目录中单独的文件。
- 每次发布都会在仓库历史中留下旧版本。万一误删或改坏：在 GitHub 上点 `data.enc` → **History** → 找到旧版本 → 下载，然后用编辑页的 **选择本地文件…** 加载并重新发布。
- 建议偶尔点 **手动导出**，把 `data.enc` 存一份到自己的电脑或网盘。它是加密的，放在哪里都安全，但必须记得密码才能打开。

## 常见问题

- **页面还是旧的样子**：GitHub Pages 会让浏览器缓存页面约 10 分钟。按 **Ctrl+F5**（Mac：**Cmd+Shift+R**）强制刷新。
- **“本站还没有 data.enc”**：仓库根目录里还没有 `data.enc`，或者刚上传还没部署完（等 1～2 分钟）。
- **截图打不开**：截图文件没有上传到 `shots/`，或者是用旧密码加密的。在编辑页编辑那条快照，重新选一次截图并发布即可。

## 运行测试

需要 Node.js 22 或更新版本，不用安装任何依赖：

```bash
node --test tests/*.test.mjs
```

修改任何 `.js` 或 `style.css` 后，把 `index.html` 和 `editor.html` 开头的版本号（`?v=…`，两处必须相同）改成新值，这样浏览器会重新下载所有文件，不会新旧混用。测试会检查两个页面的版本号是否一致。

## 注意

- 不要把明文数据、明文截图、密码或 token 提交到仓库，包括 issue 和提交说明。
- `robots.txt` 禁止所有爬虫，所有页面都带 `noindex`。但网址本身是公开的，安全性完全依赖密码强度。
- 编辑页有尚未发布或导出的修改时，关闭页面会弹出提醒。
- 如果让浏览器记住了账本密码，能使用你这台设备的人就能直接打开账本，请确保设备设了锁屏密码。
